# Private-repository owner approval — implementation review

The approval mechanism from `abeb99f` required separately enforced GitHub Environment reviewers/branch rules. Those cannot be assumed on GitHub Free private repositories. It also exposed a signing key to an editable publication workflow. The replacement keeps the repository private and moves signing/publication into independently installed, pinned owner tools. Actions now builds unsigned candidates only, with no signing secret, publication job or contents-write permission. No GitHub/VPS configuration or real publication/deployment was performed.

## Security boundaries

| Boundary             | Control                                                                                                                                   | Remaining responsibility                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Owner approval       | Exact reviewed manifest digest binds source, run ID/attempt, archive/file hashes, policy and sequence                                     | Owner reviews real source/workflow/run/artifact; green CI is not independent approval               |
| Signing key          | Encrypted Ed25519 key in private Android storage, absent from GitHub/CI/VPS; owner tools refuse CI                                        | Protect the phone/passphrase; keep encrypted recovery copy; rotate any key previously exposed to CI |
| Tool trust           | Reviewed commit/checksums, independent frozen install outside source/workflow/candidate directories                                       | Never run updated tools/policies from build artifacts or moving branches                            |
| Artifact handling    | Data-only bounded ZIP inspection, allowed paths/types, exact hashes, installed image policy, recheck after unlock                         | Approval can still authorize harmful browser JS; validation is not a source audit                   |
| Publication          | Signature and digest verification, private verified snapshot, explicit --publish, hidden expiring PAT prompt, fast-forward data-only push | PAT is repository-scoped, not branch-scoped; protect/revoke it and review unexpected branch changes |
| No paid GitHub gates | VPS trusts pinned owner signature and existing high-water sequence, not branch access/Environment controls                                | Repository writers can cause denial of service; preserve VPS state and exact first-apply approval   |
| VPS execution        | Existing site-user outbound read-only fetch; no source checkout/build/remote scripts                                                      | Verify CloudPanel binding, key/host trust, filesystem ownership and free space                      |
| Backup/recovery      | Existing verified backups, protected dot paths, locking, pending journal, rollback and dry-run unchanged                                  | Independent protected-config backup; brief mixed-version window; monitor logs/storage               |

A compromised owner signing device, trusted-tool installation, signing private key or VPS account remains outside these safeguards. A compromised GitHub repository alone cannot forge a fresh accepted release; it can replace/delete data or replay already signed releases. The existing sequence checks and exact first-deployment approval constrain replay. Account/plan features that restrict writers are useful defense in depth if available, but are not assumed for authenticity.

No actual Android session, GitHub private-repo PAT publication, real VPS outbound SSH/authentication, cron or document-root binding was exercised. Use the [owner runbook](pull-deployment.md) for separately approved setup and dry-run. No workflow was dispatched to publish; no VPS, DNS, SSL, CloudPanel, .in/.com WordPress/commercial site or repository visibility was changed. Nothing was deployed or merged.
