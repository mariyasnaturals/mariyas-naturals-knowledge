# Pull deployment preparation — validation and security review

This task prepares files only. The current repository's existing workflows published review artifacts and did not contain VPS SSH-push steps. No inbound SSH solution was added, no VPS connection was made, no release branch was published, and no merge/deploy/DNS/CloudPanel/WordPress change was performed.

## Local evidence

- Python 3/OpenSSL safety suite: **17 tests passed**. Covers dry-run with unchanged website bytes/no backups, exact first-apply approval and inventory drift, verified backups, `.well-known`/dotfile preservation, rollback and sequence replay protection, signature/archive/file tampering, wrong signed policy, unsafe/traversal/dot/server-side paths, duplicate ZIP entries, symlinks, backup corruption, partial writes, interrupted transaction recovery including leftover temp files, concurrent lock exclusion configuration/user/WordPress/public-state refusal, and local Git publication of only data with a fast-forward second release.
- Actual compiled artifact rehearsal: **435 files and 36 approved image derivatives** signed using a temporary Ed25519 test key and verified locally. Dry-run left the fixture site unchanged and created no deployment backup. A separate fixture-only apply verified its backup first, preserved `.well-known`, and rollback restored the prior page; polling did not undo the rollback. Test keys and temporary trees were destroyed. [Raw report](pull-dry-run.json).
- Existing site validation passed: Astro/TypeScript (52 files, zero errors/warnings/hints), Prettier format/lint, nine Node tests, production build (377 pages), static-page checks and .in-only media policy (377 pages, 104 image elements, 12 approved originals and 36 local derivatives). Development `.cloud` settings retain noindex/nofollow and disabled purchasing. Source/UI/assets remain identical to the approved rebrand baseline; operations-only changes do not import images or redesign the site.
- Existing Playwright suite: **24 tests passed**, including four-language mobile accessibility scans with no reported WCAG A/AA violations, desktop/mobile navigation and story behavior, reduced motion, no-JavaScript content, approved-image loading and responsive viewports. These are local Chromium checks, not physical-device or live-VPS results.

This is not a test of the actual VPS, document-root binding, ownership/permissions, available disk, GitHub outbound SSH trust/key access, cron's environment or real HTTP service. Those require the owner setup and dry-run plan in [the runbook](pull-deployment.md). The manual release workflow itself is not dispatched during this task because publication could become visible to a server poller.

## Security boundaries reviewed

| Boundary                  | Control                                                                                                                                      | Residual prerequisite                                                                                           |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Source execution          | Exact dispatch SHA on a single approved source branch; GitHub-hosted builds; no VPS runner/build                                             | Owner reviews/protects source and workflow changes                                                              |
| Publication approval      | Separate environment-gated signing job, required enable variable and secret; only manual trigger                                             | Owner must configure enforceable required reviewers/branch restrictions; environment name alone is insufficient |
| Private repository access | Read-only deploy key retained on VPS; pinned GitHub SSH host keys; outbound fetch only                                                       | Owner installs/tests credentials through Web Console; never bypass host checking                                |
| Release authenticity      | Pinned public PEM fingerprint and Ed25519 signature over archive hash, file inventory, source/sequence/site/policy                           | Protect/rotate signing key and review account access                                                            |
| Payload handling          | Exactly three branch data blobs; no checkout/hooks/submodules; ZIP type/path/size/hash/metadata/image validation; no remote script execution | Approved malicious client JS still affects visitors; signatures do not replace source review                    |
| Destination               | Exact owner-confirmed .cloud marker, site-user UID/ownership, non-symlink paths and WordPress/source sentinels                               | Owner verifies actual CloudPanel binding; script cannot infer it                                                |
| First live write          | Disabled by default; explicit --apply plus owner config and first approval of release AND current inventory                                  | No live approval is granted by this task                                                                        |
| Backup/write              | Free-space reserve, full verified non-hidden static backup before replacement, per-file atomic writes, protected dot paths untouched         | Brief mixed-version window; independent protected-config/ACME backup; no concurrent manual writes               |
| Recovery                  | Nonblocking lock; failure restore; pending journal blocks new deployment; explicit recovery/rollback; no automatic backup pruning            | Owner monitors logs/space, verifies recovery and manages retention                                              |

The dedicated release branch contains static archives and signatures only. A read-only GitHub deploy key is not the signing private key and is not a root SSH login key. No secret is placed in source, public directories or the report. No source from a release branch is executed. There are no FTP, rsync/SCP-to-VPS, DNS, SSL or CloudPanel mutation commands in any workflow.
